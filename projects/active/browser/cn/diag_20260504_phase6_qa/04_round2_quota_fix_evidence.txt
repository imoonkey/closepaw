## Code-level confirmation (item 4 sub-checks A–D)

A. **Counter ownership = session.** `sessionDecodedBytes: AtomicLong` is now declared and
   instantiated as a private member of `BrowserSessionManager`:
   - `app/src/main/kotlin/ai/closepaw/browser/script/BrowserSessionManager.kt:106`
     ```
     private val sessionDecodedBytes = AtomicLong(0L)
     ```
   It is threaded into `runnerFactory(appContext, client, sessionDecodedBytes)` at
   `BrowserSessionManager.kt:179`, then into `BrowserScriptRunner(..., sessionDecodedBytes = ...)` at
   `BrowserScriptRunner.kt:42` (constructor param) and `BrowserScriptRunner.kt:89` (passed to
   the JsInterface as `sessionDecodedBytes = sessionDecodedBytes`), then into
   `BrowserScriptJsInterface.kt:24` as a constructor parameter (no longer a private field).
   Per-call JsInterface instances within one session see the same AtomicLong.

B. **Survives markBroken reconnects.** The runner is rebuilt via `runnerFactory` on every
   reconnect (the call site that hands the counter is `BrowserSessionManager.kt:179`, inside
   the reconnect-rebuild path). `sessionDecodedBytes` is a single `private val` field on the
   manager — re-invoking `runnerFactory` reads the same field, so the new runner gets the
   same AtomicLong instance. Verified by the unit test below (D-2).

C. **Atomic CAS via getAndAccumulate.** The check-then-add pattern is replaced with one
   indivisible reservation:
   ```
   val before = sessionDecodedBytes.getAndAccumulate(byteCount) { current, requested ->
       if (current + requested > maxBytesPerSession) current else current + requested
   }
   if (before + byteCount > maxBytesPerSession) { ... reject ... }
   ```
   (`BrowserScriptJsInterface.kt:61–66`). The lambda returns `current` to refuse, so two
   concurrent JS-thread calls cannot both pass the check and both add. Reservation releases
   on `recorder.storeBytes` exception (`addAndGet(-byteCount)` at line 80) and on null return
   (`addAndGet(-byteCount)` at line 84) — quota only burns on actual stored bytes.

D. **Tests covering the fix.**
   - `BrowserScriptJsInterfaceTest.session quota is shared across JsInterface instances within one session`
     (`app/src/test/kotlin/.../BrowserScriptJsInterfaceTest.kt`): builds two distinct
     JsInterface instances sharing one AtomicLong, simulates two `run()` calls; second call's
     reservation is refused at cap; counter advances by first-call bytes only (proving CAS
     accumulator returns `current` on refuse).
   - `BrowserSessionManagerTest.storeArtifact session quota persists across browser_script invocations within one session`:
     asserts `runnerFactory` is invoked once (runner reuse across runs) and the counter is
     observable across both invocations.
   - `BrowserSessionManagerTest.storeArtifact session quota survives CDP reconnect within one session`:
     forces a reconnect via `markBroken` (transport failure on call 1) then runs again;
     asserts two runner instances built but `countersHandedOut[0] === countersHandedOut[1]`
     (same AtomicLong instance).
