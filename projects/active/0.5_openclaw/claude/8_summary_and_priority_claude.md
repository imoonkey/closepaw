# OpenClaw 产品借鉴 — 总结与优先级 (Claude)

## 与 Codex 分析的互补关系

Codex 的分析侧重产品架构和战略判断（Gateway/Node 分离、Web 控制台、onboarding 向导、安全配对模型）。

Claude 的分析侧重具体能力层面值得搬运的设计：
1. Memory 系统 → 跨任务知识积累
2. Voice-First → 语音交互闭环
3. Session 模型 → 一等对象设计
4. Agent Identity 模板 → prompt 可配置化
5. 三轴安全模型 → tool 风险分级
6. 设备能力广播 → 动态 tool 注册
7. Canvas Host → Agent 驱动的 rich UI

## 优先级排序（按 ROI）

### 第一梯队：低成本高回报，现在就能做
| # | 借鉴点 | 成本 | 回报 | 理由 |
|---|--------|------|------|------|
| 4 | System Prompt 外置 | 半天 | 高 | 改个文件就能调 prompt，eval 效率翻倍 |
| 6 | 动态 Tool 注册 | 1-2天 | 高 | 消除 "工具存在但不可用" 的浪费步骤 |
| 5 | Tool 风险分级 | 1天 | 高 | 为远程控制和高危操作打地基 |

### 第二梯队：中等成本，产品差异化
| # | 借鉴点 | 成本 | 回报 | 理由 |
|---|--------|------|------|------|
| 3 | Session 持久化 | 2-3天 | 高 | 多入口共享的前提条件 |
| 1 | App 操作经验存储 | 2-3天 | 高 | agent 越用越聪明，核心竞争力 |
| 2 | 语音输入 (Phase 1) | 1-2天 | 中 | Android SpeechRecognizer 免费，可用性质变 |

### 第三梯队：远期规划
| # | 借鉴点 | 成本 | 回报 | 理由 |
|---|--------|------|------|------|
| 7 | Rich Message | 3-5天 | 中 | 先把 agent 核心能力做强，再优化交互形式 |
| 2 | 唤醒词 | 5天+ | 中 | 锦上添花 |
| 7 | WebView Canvas | 1周+ | 中 | 只在 rich message 不够时才需要 |

## 一句话总结

OpenClaw 最值得学的不是具体功能，而是两个设计原则：
1. **能力声明式** — 设备说自己能做什么，而不是中心假设设备能做什么
2. **状态外置化** — prompt、memory、session、tool policy 全部是数据不是代码，可配置可替换
