# RetroPlaylistDuration — Failure Analysis

## Scripted Success Criteria

From `retro_music.py` lines 286-293:

```python
def is_successful(self, env: interface.AsyncEnv) -> float:
    songs = _get_playlist_data(env)
    total_ms = 0
    for song in songs:
        if song.playlist_name != self.params['playlist_name']:
            return False
        total_ms += song.duration_ms
    return float(45 * 60 * 1000 <= total_ms <= 50 * 60 * 1000)
```

The check queries Retro Music's SQLite database (`playlist.db`) via ADB, joining `PlaylistEntity` and `SongEntity` tables. It verifies:
1. All songs in the DB belong to the named playlist ("Reggae Rhythms 51").
2. The sum of `duration_ms` for those songs falls in [2,700,000 ms .. 3,000,000 ms] (45-50 minutes).

## Task Setup

From `initialize_task` (lines 260-284):

1. Clears all existing playlist databases.
2. Writes 9-11 "target" MP3 files to the device's music directory. Their durations are generated by `_generate_list_with_sum(47.5 * 60 * 1000, num_files)`, which distributes durations summing to exactly 47.5 minutes across all target files. This guarantees a valid answer exists: adding ALL target files yields exactly 47.5 minutes (within the 45-50 range).
3. Writes 4-6 "noise" MP3 files with random durations (3-5 minutes each).
4. Triggers a media scan so Retro Music indexes all files.

Key insight: the task is designed so that adding ALL target songs (and no noise songs) is the correct answer. The agent does not need to optimize a subset -- it needs to identify which songs are "target" vs "noise" and add all targets. However, the goal text says only "using the provided songs" without listing which are targets.

## Gap Analysis

1. **Duration visibility**: The Songs list view shows only song title and artist -- no duration column. The a11y tree confirms this: elements contain text like "Beyond the Horizon | Maryam" with no duration data. The screenshot also shows no visible duration field in this list view.

2. **App skill guidance exists but was not followed**: The Retro Music SKILL.md (lines 17-25) instructs the agent to either read durations from screenshots (visual perception) or open each song's 3-dot menu and check "Details" for the duration field. The agent did not attempt the 3-dot menu/Details approach.

3. **Agent gave up too early**: Only 8 turns were used (max was 50). The agent created the playlist but never attempted to discover song durations through the Details view or any alternative method.

4. **The real problem is deeper than navigation**: Even if the agent could read durations, the task requires a combinatorial decision. The setup guarantees all target files sum to 47.5 min, but the agent has no way to distinguish "target" from "noise" files. It would need to: (a) enumerate all songs and their durations, (b) find a subset summing to 45-50 minutes. With 13-16 songs and a 3-5 minute range each, this is a non-trivial knapsack calculation the agent would need to do in its scratchpad.

5. **Structural constraint**: Song durations are genuinely not in the a11y tree or the default list view. The only path is: 3-dot menu per song -> Details -> read duration. With ~15 songs, that is ~60 navigation actions just to collect data, consuming most of the turn budget before any playlist assembly.

## Revised Strategy: Incremental Add-and-Check

The original analysis concluded this is structural. But the agent doesn't need per-song durations at all. The key insight:

1. **Retro Music shows total playlist duration on the playlist page** (e.g., "47 min" or "2 Songs • 8:23").
2. The agent can add songs one at a time, check the running total after each addition, and stop when it hits 45-50 min.
3. If it overshoots, it removes the last song. If it undershoots after adding all, it tries different combinations.
4. With 9-11 target songs (avg ~4.3 min each) and 4-6 noise songs (3-5 min each), the agent can estimate ~4 min/song and add ~12 songs, then adjust.
5. The **guaranteed solution** (all target songs = 47.5 min) means a greedy add-all-then-prune strategy will likely work.

Another approach: Retro Music supports multi-select in the song list. Agent could select all songs, add to playlist, check total. If over 50 min (because noise files were included), remove songs one at a time until within range.
